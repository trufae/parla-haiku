Fixes the **32-bit Chatmail RPC server crash** during account setup.

## Downloads

- **32-bit hybrid Haiku:** `parla_x86-0.1.3-2-x86_gcc2.hpkg`
- **64-bit Haiku:** `parla-0.1.3-1-x86_64.hpkg`

Quit Parla and its stopped RPC server before upgrading. Install the matching package with `pkgman install ./filename.hpkg`. Profiles are retained. The Applications-menu entry and GUI fixes from 0.1.2 are included.

## Root cause

The reported instruction at server offset `0xfee921` is `movaps %xmm7,-0x148(%ebp)` in ring's P-256 multiplication. It requires 16-byte alignment, but the 32-bit Haiku C ABI permits a 4-byte-aligned stack. Ring enabled SSE2 in its C code without realigning the stack at entry from Rust.

This was reproduced using the released server's actual machine code: multiplication and squaring succeed at stack offset 0, and crash at offsets 4, 8 and 12. It is a separate bug from the GUI's missing-field exception fixed in 0.1.2.

## Changes

- Patch the pinned ring 0.17.13 build to enable `-mstackrealign` for Haiku x86 C code.
- Retain core function symbols and line tables for meaningful device backtraces.
- Add a 32-bit CI regression that executes the built server's actual P-256 functions at every permitted stack alignment and verifies their arithmetic results.

Cryptographic algorithms and TLS certificate verification remain unchanged.

## Verification

Both package builds pass. The 32-bit binary passes all eight multiplication/squaring alignment checks. The native 64-bit Haiku job passes account-form, layout and transport tests, real-core offline tests, package installation, and launch via the Applications shortcut.

The instruction-level test does not boot 32-bit Haiku or exercise its complete network stack. Live account creation and device transfer still need real-system testing; CI does not provision accounts or send mail.
