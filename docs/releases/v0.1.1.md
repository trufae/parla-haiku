Fixes the empty native dialogs reported on 32-bit Haiku and makes core/setup failures visible.

## Downloads

- **32-bit hybrid Haiku:** `parla_x86-0.1.1-2-x86_gcc2.hpkg`
- **64-bit Haiku:** `parla-0.1.1-1-x86_64.hpkg`

Install the matching package with `pkgman install ./filename.hpkg`. Existing profiles are retained.

## Root causes and fixes

- The shared form window had no window layout. Its child view never received usable dimensions, hiding every field and button in profile creation, device linking, backup and other dialogs. The window now owns a layout.
- Haiku clears text when password masking is enabled. Secret fields now enable masking before setting their initial value.
- Core stderr was discarded, and errors only appeared in a truncated status line. The transport now retains the last 4 KiB for disconnect diagnostics; errors show a native alert and remain available under **Profile → Last error**.
- Setup/import events were filtered out because their new account was not selected. The new account is selected before setup, and configuration/transfer progress is displayed.
- Profile settings now prefill the current display name and stop after a failed settings write. Empty email addresses and device-link codes are rejected before creating an account.
- A failed event request no longer permanently stops event polling: it retries after five seconds while the core remains connected. Read-receipt polling stops on disconnect.

The reported “Create a profile to start chatting” screen is reached only after the core responds with an empty account list. That observation points to the form layout failure, rather than a dead JSON-RPC server.

## Verification

The native Haiku test opens forms with different field counts, checks visible controls and bounds, verifies Unicode/secret values on submission, and checks cancellation. `parla-forms.png` captures a tested form. Transport tests cover stderr diagnostics, disconnects, timeouts and concurrent RPC calls. The actual core and GUI handshake are also tested inside 64-bit Haiku.

The 32-bit package is cross-built with the corrected x86_gcc2 package metadata. Live account provisioning, device transfer and 32-bit runtime behavior still need real-system testing; CI does not create live accounts or send mail.
