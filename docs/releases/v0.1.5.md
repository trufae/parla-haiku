# Parla 0.1.5 preview

Addresses two Rust networking bugs behind queued messages and stalled RPC on
Haiku: sockets were left in blocking mode, and the poll backend could lose
executor wakeups during socket registration. The bundled Mio patch configures
nonblocking sockets and preserves wake notifications until the poll loop
consumes them safely.

- Networking starts independently for each profile. Timed-out IMAP/SMTP shutdown
  tasks are aborted and joined, rather than detached.
- Diagnostics shows incoming and outgoing connectivity separately, including
  SMTP retry errors and time since the last RPC reply. “No errors reported” is
  no longer logged as an error.
- Deleted profiles disappear from the menu. Old account-list responses cannot
  restore them, stale selected IDs are validated, and rapid profile switches
  preserve the most recent choice.
- Starting a chat by email reuses an existing encrypted contact when available.
- Shorter composer, a small square attachment button, and more space for the
  conversation and sidebar. Your bubbles use the theme's accent color;
  incoming bubbles use its neutral panel color.
- Empty Saved messages and Device messages chats explain their purpose.

Verification includes an upstream-failing/patched-passing lost-wakeup test,
native nonblocking-socket checks and concurrent TCP/timer tests, real-core encrypted SMTP delivery and transient
failure recovery against loopback servers, profile lifecycle and native GUI
tests, and the 32-bit crypto stack-alignment regression.

The 32-bit package is `parla_x86-0.1.5-2-x86_gcc2.hpkg` for Haiku's hybrid x86
installation. The 64-bit package is `parla-0.1.5-1-x86_64.hpkg`.

Quit Parla before upgrading, then reopen it. Existing queued messages are retried
by Chatmail; do not manually resend them just because an earlier request timed
out. If sending still stalls, open **Profile → Diagnostics** and photograph the
incoming/outgoing summary and latest log entries. The real 32-bit device and its
mail provider still need user validation; loopback testing does not verify that
provider's TLS, credentials or network reachability.
