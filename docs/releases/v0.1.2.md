Fixes the account-creation abort reported on 32-bit Haiku and installs Parla in **Deskbar → Applications**.

## Downloads

- **32-bit hybrid Haiku:** `parla_x86-0.1.2-2-x86_gcc2.hpkg`
- **64-bit Haiku:** `parla-0.1.2-1-x86_64.hpkg`

Quit Parla and install the matching package with `pkgman install ./filename.hpkg`. Existing profiles are retained.

## Root causes and fixes

- Haiku's `BMessage::FindString` clears its output pointer on failure. New-profile and device-link forms contain two fields, but the shared account handler unconditionally read a third. Constructing `std::string` from that null pointer throws, and the exception escaped the window looper, producing `std::terminate` / `abort`. Missing strings now use a checked empty fallback.
- `FindUInt32` similarly clears its output on failure. Menu/drop messages without explicit account/chat IDs silently lost the current selection. Defaults now use `GetUInt32`, fixing affected profile settings, backup export and dropped-attachment paths.
- Unnamed profiles return a JSON null display name; settings now opens with an empty field instead of doing nothing.
- Malformed draft IDs could throw during startup; draft IDs and quote IDs are checked before conversion.
- Window message handling now reports C++ exceptions in the native error alert instead of unwinding through Haiku's looper. Startup failures also show an alert. GUI binaries retain debug information for future backtraces.
- The package's shortcut was outside the Applications directory. It now installs `data/deskbar/menu/Applications/Parla` with a verified relative target.

## Verification and limits

Both architectures build successfully. Native 64-bit Haiku tests submit the actual new-profile, device-link, email-login and settings forms through MainWindow to an offline RPC fixture, verifying outgoing methods/arguments and Unicode/password values. They also check selected-account fallback, missing-field validation, malformed saved drafts and recovery after an invalid response. Existing form-layout and transport tests run too.

CI installs the hpkg, checks its Applications shortcut, and launches the installed application through the shortcut with the bundled real Chatmail core. The real-core offline integration tests remain enabled.

CI does not provision live accounts, transfer a live account or send mail. The 32-bit build is cross-compiled and still requires real-system runtime testing. The stripped photograph backtrace cannot identify a source line; the fixed null-string path is a concrete code defect matching the reported action and abort mechanism.
