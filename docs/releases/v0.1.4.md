Fixes incomplete-profile recovery and adds native diagnostics for account setup and stalled sends, plus a more compact chat interface.

## Downloads

- **32-bit hybrid Haiku:** `parla_x86-0.1.4-2-x86_gcc2.hpkg`
- **64-bit Haiku:** `parla-0.1.4-1-x86_64.hpkg`

Quit Parla before installing the matching package with `pkgman install ./filename.hpkg`. Existing profiles are retained. The Applications-menu entry and the 32-bit crypto stack fix remain included.

## Profile recovery and management

Saving a name previously called legacy `configure()` on every incomplete profile, including Chatmail and failed device transfers that had no legacy email credentials. That produced “Missing email address” instead of retrying the intended operation.

Profile settings now separates saving your name from setup. An incomplete profile offers explicit **Set up Chatmail**, **Use email**, and **Link device** actions that reuse that profile. Email setup uses the current `add_or_update_transport` API. A profile is only reported ready after configuration and `start_io` both succeed.

Settings shows configured relay addresses, IMAP/SMTP hosts, and the accounts directory. **Delete this profile** asks for confirmation, then uses Chatmail's `remove_account` to stop IO, close the database and remove that profile's local database and attachments. Other devices are unaffected; local drafts for the deleted profile are also removed.

Parla already explicitly passes `DC_ACCOUNTS_PATH` to its private server. The default is `/boot/home/config/settings/Parla/accounts`; an explicit environment override remains supported. **Open accounts folder** opens the actual location in Tracker. Quit Parla before manually resetting that directory.

## Reporting a stalled send

Open **Profile → Diagnostics** (or the **Diagnostics** button on an error alert). Reproduce the failure, select **Pause updates**, and photograph the latest error and relevant log lines. The window wraps text, keeps the latest error above the log, and supports copying the full report.

Reports contain version, architecture, actual account/server paths, timestamped RPC method/request IDs and timings, result summaries, core events, and live server stderr. Password/setup-code parameters and message-body responses are not dumped. Core logs may contain server addresses and account metadata.

A bounded report is saved as `diagnostics.log` in Parla's settings folder; the previous run is retained as `diagnostics.previous.log`. These files use owner-only permissions. No log is uploaded automatically.

Queued messages are distinguished from messages sent to the server. Later `MsgFailed` events fetch and expose the stored sending error. Timeouts identify the unanswered method, profile, request ID and elapsed time. After a setup timeout, Parla requests cancellation before enabling another attempt. Sending is never automatically repeated after an unknown-result timeout.

The known “Missing email address” retry bug is fixed. The earlier screenshots and generic timeout do not establish why live sending stalls on the reported x86 machine; these diagnostics are intended to capture that cause, rather than claim an unverified network fix. TLS verification remains enabled, with the child process explicitly using Haiku's installed CA bundle unless overridden.

## Native interface

- Compact composer with attachment and Send buttons on the same row.
- Contact avatars, initials when no picture exists, and chat-list previews.
- Incoming/outgoing message cards with quieter timestamps and delivery states in the footer.
- Earlier-message button only appears when there are older messages to load.

## Verification

Native Haiku tests cover failed Chatmail setup and retry on the same profile, email and transfer RPCs, editing settings, simulated asynchronous SMTP failure, private-payload omission from diagnostics, compact composer bounds, and profile deletion. Portable transport tests cover concurrent replies, partial reads, live bounded stderr, timeout and server termination. Real-core offline tests, package installation and launch via the Applications shortcut are also run. The 32-bit artifact retains the eight actual-machine-code crypto ABI checks.

Live account provisioning and mail delivery on 32-bit Haiku still require real-system testing. CI does not send mail or create public accounts.
